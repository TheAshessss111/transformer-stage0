### 0.2 (B) Introduce `TracedProgram` — a declarative program, not ad-hoc instrumentation

**This is the load-bearing addition and the one I most want signed off.**

F0.3.3 (frames) and F0.3.4 (code-line binding) look like two features. They are
one, and solving them separately produces a mess. The obvious approach —
tagging individual ops with line numbers — is verbose at every call site, breaks
whenever the code is edited, and gives the playhead the wrong granularity: a
person reads a *statement*, not a primitive op.

Instead a lab declares its forward pass as an ordered list of steps, each with
its source text and a run function:

```ts
const SOFTMAX_FORWARD = defineProgram<SoftmaxState>({
  id: 'softmax-forward',
  language: 'python',
  steps: [
    {
      code: 'row_max = x.max(axis=-1, keepdims=True)',
      note: { zh: '每一行取最大值，形状留成 (B, 1)', en: 'Row maxima, kept as an axis of extent 1' },
      run: (s) => ({ rowMax: max(s.x, -1, true) }),
    },
    {
      code: 'z = x - row_max',
      note: { zh: '平移，不改变结果', en: 'The shift that changes nothing' },
      run: (s) => ({ z: sub(s.x, s.rowMax) }),
    },
    // …
  ],
});
```

One declaration then yields, for free:

| Need | Where it comes from |
|---|---|
| CodePane source text | concatenated `code` |
| Current line highlight | the running step's line range |
| Playhead frames | one frame per step (with op-level events inside) |
| `note` for "what is happening now" | `step.note` |
| **Tensor names** | **the state keys** — `s.rowMax` is addressable as `{kind:'tensor', name:'rowMax'}` |

That last row is the part that makes E0.4 possible at all. Without named tensors
there is nothing for a formula term to point *at*.

## 1. E0.3 — Design Notes

### 1.1 Three layers, already one-third built

```
RawOpEvent        emitted by every operator          ← EXISTS (E0.2)
   ↓  Recorder: assign identity, resolve producers, attach names
TraceEvent        one primitive operation
   ↓  group by program step
TraceFrame        one source statement
   ↓
Trace             the whole execution, plus named tensors and timing
```

### 1.2 Identity: the event index, not the object

The DAG, the playhead and the highlight bus all need to name a node, and those
names must survive a recompute — otherwise moving a slider drops whatever the
user was hovering.

`NdArray` has no id, and assigning one per recording would change on every
recompute. **The stable identity is the event's position in the sequence.** The
same program run with different values emits the same sequence of operations, so
event 7 is event 7 across recomputes.

Tensors get names from the program's state keys (§0.2). Between the two,
everything on screen is addressable:

```
{ kind: 'event',  index: 7 }              a DAG node, a code line's operation
{ kind: 'tensor', name: 'rowMax' }        a named intermediate
```

### 1.3 Producer edges by object identity

To draw the graph, each event's inputs must be linked to the event that produced
them. Object identity is enough: every operator allocates a fresh `NdArray`, so a
Map from output array → event index resolves inputs exactly. Inputs missing from
the map are program inputs, i.e. source nodes.

**One special case.** `ascontiguousarray` returns *the same object* when its
input is already contiguous (that identity is part of contract C1). That would
resolve to a self-edge. Such events are marked `passthrough: true` and are
skipped when building the graph, while still appearing in the raw event list —
because "this call cost nothing" is exactly what Step 0.1 wants to show.

### 1.4 The immutability contract

A recorded trace holds live `NdArray` references, and some of them are views
sharing a buffer. So:

> **A `Trace` is valid only for the execution that produced it. Nothing may
> mutate an array reachable from a trace. Editing an input means changing the
> lab's state and re-running the program, which produces a new `Trace`.**

This matters for F0.5.3 (click a cell to edit): the edit must go through the
lab's state and trigger a recompute, never write into a recorded array. Stated
here because it is the kind of thing that produces an impossible bug three epics
later.

### 1.5 Why suppression matters more than it looks

`vjp.ts` and `softmax.ts` already run their internal helpers under
`suppressOpHook`, so the backward trace has one event per operator rather than
exposing the four primitives inside `softmaxVjp`. That decision was made in E0.2
and E0.3 depends on it: without it, frames would be full of noise and the DAG
would show plumbing instead of mathematics.

`softmaxSteps` is the escape hatch when a lab *wants* the internals (F0.8.2).

### 1.6 Throttling (F0.3.5)

Recompute is synchronous and fast; the risk is doing it several times per frame
while a slider is dragged. `useTracedProgram` coalesces with
`requestAnimationFrame`: at most one run per frame, latest inputs win, no queue.

Budget: **≤ 8 ms per run** for teaching-scale tensors (≤ 4096 elements), leaving
half a 16 ms frame for React and paint. `/dev/trace` measures and displays p50 /
p95 so NFR-2 is a number on screen rather than a hope.

`src/core/trace/program.ts`

```ts
export interface ProgramStep<S> {
  /** Source text for CodePane. May span several lines. */
  code: string;
  /** "What is happening here", bilingual. */
  note?: L;
  /** Returns the state keys this step produces. Keys become tensor names. */
  run: (state: Readonly<S>) => Partial<S>;

  phase?: 'forward' | 'backward';

  language: 'python' | 'typescript';
  steps: readonly ProgramStep<S>[];
}): TracedProgram<S>;
```

`defineProgram` joins the `code` strings with newlines and precomputes each
step's 1-indexed line range, so `CodePane` can highlight a range without

### T22 · `Recorder` — RawOpEvent → TraceEvent  →  F0.3.1

`src/core/trace/types.ts`, `src/core/trace/recorder.ts`

```ts
export interface TraceEvent {
  index: number;                  // stable identity (§1.2)
  step: number;                   // which program step emitted it
  phase: 'forward' | 'backward';
  op: string;
  inputs: readonly {
    event: number | null;         // producing event, or null for a program input
    name: string | null;          // state-key name if it has one
    shape: readonly number[];
  }[];
  output: {
    name: string | null;
    shape: readonly number[];
    array: NdArray;               // see the immutability contract, §1.4
  };
  isView: boolean;
  didCopy: boolean;
  copiedElements?: number;
  passthrough: boolean;           // output === input (§1.3)
  meta?: Readonly<Record<string, unknown>>;
}

export interface Trace {
  programId: string;
  events: readonly TraceEvent[];
  frames: readonly TraceFrame[];
  /** Named tensors from the program state, in creation order. */
  names: ReadonlyMap<string, NdArray>;
  durationMs: number;
}

export function runProgram<S extends object>(
  program: TracedProgram<S>,
  initial: S,
): { state: S; trace: Trace };
```

`runProgram`:
1. seeds a `WeakMap<NdArray, number>` with `null` producers for every array in `initial`, and records their state keys as names
2. installs a hook via `withOpHook` (never `setOpHook` directly — nested recording must not leak)
3. runs each step, tagging every event with the step index
4. after each step, walks the returned `Partial<S>` and records each new array's key as its name
5. resolves each event's input producers through the WeakMap
6. marks `passthrough` where `output === inputs[0]`
7. times the whole thing with `performance.now()`

**DoD**
- [ ] Producer edges correct for a chain, a diamond, and a program input
- [ ] `passthrough` set exactly for a no-op `ascontiguousarray`, and nowhere else
- [ ] Names resolved for every state key; unnamed intermediates carry `name: null`
- [ ] Two runs of the same program with different values produce identical `index`/`step`/`op` sequences (identity is stable — §1.2)
- [ ] Nested `runProgram` restores the outer hook
- [ ] Commit: `feat(core): recorder with stable identity and producer edges`

```ts
export interface TraceFrame {
  index: number;
  step: number;
  phase: 'forward' | 'backward';

  lineStart: number;
  lineEnd: number;
```

## 3. E0.4 — Design Notes

### 3.1 The overlap matcher, not equality

Components do not compare highlight targets for equality — they ask whether two
targets *could refer to the same thing*. Hovering the whole tensor `s` should
light every cell of `s`; hovering cell `[0, 2]` should light the tensor's label
and the formula term that points at `s`.

So the primitive is symmetric overlap, not equality:

```ts
export function overlaps(a: HighlightTarget, b: HighlightTarget): boolean;
```

| Pair | Overlap when |
|---|---|
| tensor / tensor | same `name`, and indices are compatible (a missing index means the whole tensor; `'*'` matches any position) |
| tensor / axis | same tensor name |
| axis / axis | same tensor and same axis |
| formula / formula | same `eq` and same `term` |
| code / code | same line |
| event / event | same index |
| anything / different kind | never |

Cross-kind linkage is **not** done by the matcher. It is done by *declaration*: a
formula term declares the tensor targets it corresponds to, and the store
resolves through those declarations. Trying to make the matcher itself
cross-kind would bake content decisions into a generic utility.

### 3.2 The re-render trap, and how the store avoids it

A 16×16 `TensorGrid` is 256 cells. If highlight state lives in a React Context
whose value changes on every `pointermove`, all 256 re-render per mouse move,
plus the formula, plus the code pane. That is the single most likely way to make
this app feel bad, and it will not be obvious until E0.5 when the grids are real.

So highlight state lives in an **external store** read through
`useSyncExternalStore` with a *boolean-ish* selector:

```ts
export type HighlightLevel = 'none' | 'hover' | 'pinned';
export function useHighlightLevel(target: HighlightTarget): HighlightLevel;
```

`getSnapshot` returns one of three strings, so React bails out of re-rendering
any component whose own level did not change. Hovering one cell re-renders that
cell and whatever else genuinely overlaps it — not the grid.

Two mechanical requirements, both easy to get wrong:

- `subscribe` and `getSnapshot` must be referentially stable, or the component
  resubscribes every render. The hook memoizes both on `targetKey(target)`.
- `targetKey` must be a total, injective serialization, since it is the memo key
  and the pin-set membership key.

### 3.3 Two levels: hover and pinned

- **hover** — at most one, transient, cleared on pointer-out.
- **pinned** — a set, toggled by click, survives pointer movement.

Pinning is what makes comparison possible: pin `s̄` and `s`, then read the
formula with both lit. Multi-pin is the point; a single-pin design would not
support the comparisons Steps 0.3 and 0.4 are built on.

Precedence when both apply: `pinned` wins, so a pin does not flicker while the
pointer crosses it.

### 3.4 Formula authoring

Authors write LaTeX with one custom macro:

```
\bar x_i = \frac{1}{\hat\sigma}\left[
  \term{direct}{g_i}
  - \term{de-mean}{\frac{1}{D}\sum_j g_j}
  - \term{de-scale}{\hat x_i \frac{1}{D}\sum_j g_j \hat x_j}
\right]
```

`\term{id}{content}` expands to KaTeX's `\htmlData{term=id}{content}` (pending
the T27 spike), producing `data-term="id"` in the output. The `Formula`
component then uses **one delegated listener** on the container and
`event.target.closest('[data-term]')` — never N listeners for N terms.

Term metadata lives beside the LaTeX, not inside it:

```ts
export interface TermSpec {
  label: L;                       // "what this term is"
  purpose: L;                     // "what it is doing"
  shape?: string;                 // "(B, T, 1)" — the plan's symbols
  read?: (ctx: LabContext) => NdArray | number | undefined;   // "the value right now"
  highlight?: readonly HighlightTarget[];                     // what it points at
}

export interface EquationSpec {
  id: string;
  latex: string;
  display?: boolean;
  terms: Readonly<Record<string, TermSpec>>;
}
```

### 3.5 Author-time validation

A term present in the LaTeX but missing from `terms` produces a tooltip that
silently does nothing — the worst kind of bug, because the page looks finished.

`validateEquationSpec(spec)` extracts every `\term{…}` by regex and diffs it
against `Object.keys(spec.terms)`, reporting both directions. It runs in dev on
every render (memoized on `latex`) and throws; it is stripped in production. It
is a pure function with no DOM dependency, so the verify harness checks it too.

### 3.6 The tooltip is four panes, always in the same order

What / shape / value now / purpose. Fixed order so the eye learns where to look,
and every pane present even when empty (an absent `read` shows "not bound"
rather than collapsing the layout).

The "value now" pane is what makes this more than a glossary: it reads live from
the lab's current state via `read(ctx)`, so dragging a slider changes the number
inside the tooltip.

### What changed during implementation

1. **Highlight state holds a group, not a single target.** Pointing is usually
   plural — the LayerNorm de-scale term is about x̂ *and* g — and forcing a
   caller to pick which one "really" counts would be arbitrary. `setHover` and
   `togglePin` take a target or a list; a group pins as one unit, with
   order-independent identity.

2. **`targetKey` had to become a real bijection.** Subscriptions are memoized on
   the key rather than the target object, because an inline
   `{ kind: 'tensor', name, index }` changes identity every render and would
   resubscribe every render. That required `parseTargetKey`, and the round trip
   is now checked.

3. **React re-applies `dangerouslySetInnerHTML` even when the html is
   byte-identical.** Verified directly: the container node survives, the child
   nodes do not. Anything an effect writes onto KaTeX output is destroyed on the
   next render, so highlighting would have silently stopped working after any
   unrelated state change — an invisible bug. `Formula` now re-applies its
   attributes in a layout effect after *every* commit, with no dependency array.

4. **Leaf views must be memoized or the store's whole point collapses.** A grid
   label subscribing to the whole tensor re-renders the grid on any cell hover;
   without `memo` on the cell that re-renders all of them. Measured before the
   fix: 48/48 cells on one hover. After: 1 of 96. This is now rule 1 of §6 in
   `docs/architecture/trace.md`, because E0.5's real `TensorGrid` will hit it.

5. **The `verify:engine` rename touched nine call sites, not five.** The plan
   listed five; the GitHub workflow commits had since added the README, the PR
   template, the DoD checklist, the bug issue template and the roadmap's R-04
   entry.

6. **`.ts` import extensions now follow a rule, not a layer.** It is no longer
   "core/ uses them" but "anything the harness can reach uses them" — which now
   includes `viz/highlight/store.ts` and `viz/formula/validate.ts`. `termsInLatex`
   moved out of `render.ts` into `validate.ts` so the latter carries no katex
   import and stays Node-reachable.

7. **The i18n move dropped its re-export shim.** The plan proposed leaving one;
   nine importers is few enough to just update, and a shim is dead code.
