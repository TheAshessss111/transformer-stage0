# 需求规格：Stage Zero

> **一句话定义**：一个桌面端交互式网页，把 `transformer_plan.md` 阶段 0 的五个 Step 变成「看得见的数学」——
> 看到操作就知道 shape 怎么变，看到公式就知道每一项在算什么、值是多少、为什么要有它。

---

## 1. 问题陈述

`transformer_plan.md` 阶段 0 的目标是：**能在白纸上不查资料手推 softmax 和 LayerNorm 的反向**。
纸面文档在这里有三个说不清的东西：

| 说不清的东西 | 具体表现 | 本项目的解法 |
|---|---|---|
| **形状的物理含义** | `reshape(B,T,H,Dh).transpose(0,2,1,3)` 和 `reshape(B,H,T,Dh)` 都是合法代码，输出形状相同，但一个对一个错 | 真实 stride 语义的引擎 + 3D 内存布局可视化，直接看到数据被错配到哪个头 |
| **公式每一项的作用** | `x̄_i = (1/σ̂)[g_i − mean(g) − x̂_i·mean(g·x̂)]` —— 三项各是什么，看不出来 | 公式项逐个可悬停，弹出形状 / 当前值 / 作用；并能单独关掉某一项看后果 |
| **数值灾难的因果链** | 「忘了除 sqrt(Dh) 会梯度消失」是一句断言，不是一次体验 | 危险操作沙盒：现场把它关掉，看 logits 方差爆炸、softmax 饱和、梯度归零 |

---

## 2. 目标用户与使用场景

**主用户**：你本人，正在推进 `transformer_plan.md` 阶段 0。
**次要用户**：面试官 / 技术同行（只浏览，不动手）。

| 场景 | 频率 | 关键需求 |
|---|---|---|
| 第一次学某个 Step | 每 Step 一次 | 五段模板的顺序阅读；单步播放；推导逐步展开 |
| 手推卡住了回来查 | 高频 | 快速跳到某个公式项，看它的形状和当前值 |
| 写完 NumPy 实现后自测 | 每 Step 一次 | 沙盒里粘贴实现 → 自动 gradcheck → 相对误差报告 |
| 建立数值直觉 | 不定期 | 滑块乱调、编辑矩阵元素、触发 NaN，看后果 |
| 面试前复习 / 展示 | 低频 | 招牌可视化能一屏说清一个结论 |

## 3. 功能需求

### FR-1 内容与导航

- FR-1.1 五个 Step 各一个页面，统一五段模板：**目标 → 形状契约 → 数学要点 → 实现要点与坑 → 实现挑战**
- FR-1.2 侧栏 Step 导航 + 段内锚点导航，显示当前位置
- FR-1.3 全站中英切换，语言选择持久化
- FR-1.4 落地页：项目是什么、五个 Step 一览、每个 Step 的招牌可视化缩略入口
- FR-1.5 视口 < 1280px 时显示「请用桌面浏览器打开」拦截页

### FR-2 张量引擎（数值地基）

- FR-2.1 所有数值 **float64**（gradcheck 的硬性要求）
- FR-2.2 真实的 **view / copy 语义**：`transpose` 只改 strides；`reshape` 在非连续时必须先复制，且这次复制要在 UI 上可见
- FR-2.3 完整广播规则，含反向的 unbroadcast（沿被广播轴求和）
- FR-2.4 算子覆盖阶段 0 所需：matmul / add / sub / mul / div / exp / log / sum / mean / max / relu / softmax / log_softmax / layernorm / cross_entropy
- FR-2.5 每个算子配套手写 VJP
- FR-2.6 tape-based 微型 autograd（拓扑排序 + 反向遍历）
- FR-2.7 固定种子 PRNG，保证同一参数下结果可复现
- FR-2.8 显式雅可比构造器（**仅供 n ≤ 16 的教学演示**，用于 Step 0.3 的对照）

### FR-3 执行追踪（Trace）

- FR-3.1 引擎在「录制模式」下记录每一步：算子名、输入/输出张量 id、形状、是否是 view、是否发生内存复制
- FR-3.2 Trace 可转成帧序列，前向段与反向段分离
- FR-3.3 每个 trace 事件可绑定参考实现的代码行号
- FR-3.4 **所有动画、单步播放、代码行高亮均由 trace 驱动**，不手写动画脚本

### FR-4 可视化原语

- FR-4.1 `TensorGrid`：2D 切片热力图 + 数值叠加 + 正负发散色阶 + 悬停/钉选 + 区域高亮
- FR-4.2 `TensorGrid` 编辑模式：点击单元格改数值，触发下游全链路重算
- FR-4.3 高维切片器：> 2D 张量选择查看哪个 `(b, h)` 切片
- FR-4.4 `TensorCube3D`：可旋转的多维张量块（Step 0.1 招牌）
- FR-4.5 `MemoryStrip`：线性内存条 + stride 跳跃箭头
- FR-4.6 `ShapePipeline`：形状胶囊流水线，标注每步操作、是否复制
- FR-4.7 `GraphDAG`：计算图，前向/反向双向播放，边上流动真实梯度张量（Step 0.2 招牌）
- FR-4.8 `Vector3DScene`：3D 向量与平面（Step 0.4 招牌）
- FR-4.9 `Playhead`：播放 / 暂停 / 单步 / 回退 / 进度拖拽
- FR-4.10 `SliderRow`：受约束滑块组（如 `D % H == 0` 自动约束）
- FR-4.11 `CodePane`：只读代码 + 当前行高亮 + 该行产出形状浮标
- FR-4.12 `DistributionStrip`：一维分布直方图（看 softmax 饱和、LN 前后分布变化）

### FR-5 公式系统

- FR-5.1 KaTeX 渲染，所有公式来自内容数据而非硬编码 JSX
- FR-5.2 公式项通过 `\htmlId` 挂载 id，可悬停/点击
- FR-5.3 每个公式项绑定元数据：`{ 说明（双语）, 形状, 取值器 }`，悬停显示「这一项是什么形状、现在的值、它在干什么」
- FR-5.4 `DerivationSteps`：推导逐步展开，每步一句「为什么可以这样变」
- FR-5.5 公式项、矩阵单元、代码行、DAG 节点四者通过统一的**联动总线**互相点亮

### FR-6 Pyodide 代码沙盒

- FR-6.1 Pyodide 在 Web Worker 中运行，**懒加载**：进入实现挑战或对拍面板时才初始化，带明确进度提示
- FR-6.2 CodeMirror 6 Python 编辑器，预填与 `transformer_plan.md` 一致的骨架/签名
- FR-6.3 `NdArray ⇄ numpy` 双向传输
- FR-6.4 用户代码异常捕获，回传可读的 Python traceback
- FR-6.5 自动 gradcheck：中心差分（float64，ε=1e-5）+ 相对误差判定 + **逐元素误差热力图**（定位错在哪一项而不只是「失败」）
- FR-6.6 沙盒代码按 challenge id 存 `localStorage`
- FR-6.7 **对拍面板**：同一随机输入下 TS 引擎 vs NumPy，显示 max abs / max rel 误差；进入每个 Step 时自动跑一次自检

### FR-7 各 Step 专属实验室

见 `docs/planning/roadmap.md` 的 M0–M4，每个 Lab 均在那里列为独立功能项。

## 4. 非功能需求

| 编号 | 需求 | 指标 |
|---|---|---|
| NFR-1 | 首屏可交互 | < 1.5s（Pyodide 不计入，因其懒加载） |
| NFR-2 | 滑块拖动响应 | 教学规模张量（元素数 ≤ 4096）下 60fps；超过则节流重算 |
| NFR-3 | Pyodide 首次加载 | ≤ 15s，全程有进度反馈，且不阻塞主线程 |
| NFR-4 | 数值正确性 | 对拍面板 max rel err < 1e-12（同为 float64，应远优于 1e-5） |
| NFR-5 | 可扩展性 | 新增一个 Step 只需加一个内容文件 + 若干 Lab 组件，不改框架代码 |
| NFR-6 | 双语一致性 | 文案节点类型强制 `{ zh, en }` 双字段，缺失即编译报错 |
| NFR-7 | 视觉可读性 | 发散色阶在暗色底上对正负梯度可区分；数值不因色块变化而不可读 |
| NFR-8 | 仓库体面度 | README 含演示 GIF；提交历史干净；lint 无警告 |

## 6. 验收：这个项目做成了什么样才算成功

1. 你能对着 Step 0.1 的 3D 视图，向别人解释清楚 `reshape(B,H,T,Dh)` 错在哪 —— 用图，不用嘴硬。
2. 你能悬停 LayerNorm 反向公式的第三项，说出它的形状、它现在的值、以及关掉它会发生什么。
3. 你在沙盒里手写的 `softmax_backward` 和 `layernorm_backward` 都通过了自动 gradcheck，相对误差 < 1e-7。
4. 你能在危险操作沙盒里现场制造至少 4 种 NaN，并指出它们各自的第一个出错步骤。
5. 对拍面板证明整个 TS 引擎与 NumPy 数值一致 —— 也就是说，页面上的每一个数字都可信。
6. 这个仓库可以直接甩链接给面试官。
